# VIV 독립 설치

에이전트에게 다음과 같이 요청할 수 있다.

> 이 저장소의 VIV를 Windows에 원샷으로 설치해 줘. 사용할 환경을 먼저 물어보고, 내 선택에 맞춰 앱·서버·MCP를 설치하고 확인해 줘.

**VIV PC** 주소가 나오면 앱을 먼저 열 수 있습니다. 모바일이나 MCP는 필요할 때 같은 폴더에서 이어서 설정하세요. [앱 열기와 조회 복구](#앱-열기와-조회-복구) · [연결 복구](#연결-복구) · [첫 모의 실습](viv-mcp-playbook.md#첫-모의-실습)

## Windows 서버와 휴대폰

1. 에이전트는 **“VIV를 어느 환경에서 사용하실 건가요? 1. PC / 2. PC와 모바일 둘 다 / 0. 취소”**라고 한 번 묻는다. 사용자 메시지에 환경이 명확하면 그 선택을 바로 사용한다. 번호와 자연어를 모두 받아들이고 취소하면 설치를 시작하지 않는다.
2. 접근 가능한 Git 저장소를 새 Windows 폴더에 clone한다. 아래 명령을 실행하면 선택 메뉴가 나온다. 에이전트는 답을 받은 뒤 `-Target PC` 또는 `-Target PCMobile`을 전달한다. Windows의 Node.js 24 이상과 npm을 확인하고, 필요하면 WinGet으로 Node.js LTS를 설치한다. 잠금 파일로 앱을 빌드하고 이 checkout의 `.runtime/self-host.sqlite`에서 서버를 실행한다. Codex는 기본값으로 MCP를 등록한다. Claude Code는 `-Client Claude`를 전달한다. 다른 AI 앱에서는 `-Client Manual`로 실행해 해당 클라이언트에 지원되는 연결 방법을 사용한다.

   ```powershell
   powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\install-viv.ps1
   ```

3. 모바일을 선택한 경우에만 Tailscale을 준비한다. PC에서 사용자가 자기 계정으로 로그인하고, 필요한 경우 자기 tailnet에서 MagicDNS와 HTTPS 인증서를 활성화한다. 인증서를 발급하면 장치의 전체 도메인 이름이 공개 인증서 로그에 남을 수 있다. 앱 접근은 tailnet 규칙을 따른다. 다른 앱이 사용하는 경로나 공개 Funnel 설정이 있으면 PC 앱과 MCP를 쓸 수 있게 두고 모바일에 필요한 조치를 알려준다. VIV는 비공개 주소의 접속을 단일 소유자 세션으로 처리하므로 tailnet에서 접근 가능한 장치와 사용자 범위를 확인한다. [Tailscale HTTPS 안내](https://tailscale.com/docs/how-to/set-up-https-certificates)
4. 같은 tailnet에 로그인한 휴대폰에서 결과의 `mobileInstallUrl`을 연다. 주소가 필요하면 PC의 **설정 → 서비스 연결 → 휴대폰 연결·설치**에서 다시 확인하거나 복사한다. Android에서는 **웹앱으로 설치** 버튼이 보이면 누른다. 버튼이 없으면 Chrome의 **더보기 → 설치** 또는 **홈 화면에 추가**를 사용한다. iPhone에서 메신저로 링크를 열었다면 **Safari용 주소 복사**를 누르고 Safari 주소창에 붙여 넣는다. 복사가 제한되면 화면에서 선택된 주소를 복사한다. Safari에서 **공유 → 홈 화면에 추가**를 누르고 **웹 앱으로 열기**가 보이면 켠 뒤 **추가**를 누른다. 홈 화면 아이콘에서 VIV를 열어 PC와 같은 작업 공간인지 확인한다. [Apple 홈 화면 추가 안내](https://support.apple.com/ko-kr/guide/iphone/iphea86e5236/ios)
5. 선택한 연결에 후속 조치가 필요하면 [연결 복구](#연결-복구)에서 해당 단계만 실행하세요. 서버가 꺼져 있으면 [서버 다시 시작](#서버-다시-시작)을 확인하세요. 오류 로그는 VIV 폴더의 `.runtime/self-host.stderr.log`에 있습니다.

Codex 외의 AI 클라이언트나 앱을 설치한 뒤 MCP만 연결하는 방법은 [VIV MCP 플레이북](viv-mcp-playbook.md)을 따릅니다.

## Mac 서버와 휴대폰

저장소를 복제한 뒤 `bash scripts/install-viv-mac.sh`를 실행합니다. 에이전트는 환경을 먼저 물어보고 `--target pc` 또는 `--target mobile`을 전달합니다. 기본 MCP 클라이언트는 Codex입니다. Claude Code는 `--client claude`, 기타 클라이언트는 `--client manual`을 사용합니다.

설치 스크립트는 필요한 경우 Apple Silicon 또는 Intel용 Node.js 24를 받아 해시를 검증한 뒤 VIV 폴더 안에 설치합니다. Mac을 재시작했다면 [서버 다시 시작](#서버-다시-시작)을 따르세요. 서버 오류는 `.runtime/self-host.log`에서 확인합니다.

모바일을 선택하면 기존 Tailscale을 사용하거나 Homebrew를 통해 설치합니다. macOS VPN 승인과 Tailscale 로그인은 사용자가 진행합니다. Homebrew가 없는 Mac에서 Tailscale이 필요하면 공식 앱을 설치한 뒤 `mobileRetryCommand`를 실행합니다. 비공개 HTTPS 연결이 확인되면 `mobileInstallUrl`을 같은 tailnet에 로그인한 휴대폰에서 엽니다. [Tailscale Mac 설치](https://tailscale.com/docs/install/mac)

## 설치 결과 읽기

Windows와 Mac 모두 터미널에 앱·MCP·모바일 상태를 표시합니다. 재시도 명령은 VIV 폴더에서 실행하세요.

| 결과 | 다음 행동 |
| --- | --- |
| `desktopStatus: started` 또는 `reused` | `desktopUrl`을 열어 VIV 화면을 확인하세요. `started`는 새 서버를 시작한 경우이고 `reused`는 실행 중인 서버를 그대로 쓰는 경우입니다. |
| `restartCommand` | 앱 주소가 열리지 않을 때 기존 VIV 폴더에서 이 명령을 실행하세요. |
| `mcpStatus: registered` | AI 대화에 `onboardingPrompt`의 문장을 입력하세요. [첫 모의 실습](viv-mcp-playbook.md#첫-모의-실습)으로 이어갑니다. |
| `mcpStatus: not-requested` | 모바일 복구만 실행했습니다. AI를 연결하려면 [MCP만 복구하기](#mcp만-복구하기)를 따르세요. |
| `mcpStatus: endpoint-ready` | VIV 서버의 MCP 주소가 응답합니다. AI에 같은 `mcpUrl`이 이미 등록돼 있으면 그 연결을 쓰세요. 새 주소라면 [MCP만 복구하기](#mcp만-복구하기)에서 등록합니다. |
| `mobileStatus: phone-install-pending` | PC에서 비공개 HTTPS 주소를 검증했습니다. `desktopInstallUrl`에서도 설치 주소를 확인하고 복사할 수 있습니다. 휴대폰에서 `mobileInstallUrl`을 열고 홈 화면 아이콘에서 VIV가 열리는지 확인하세요. |
| `mobileStatus: not-requested` | 이번 실행에서 모바일 설정을 진행하지 않았습니다. 이전에 연결한 휴대폰에서는 기존 VIV 아이콘을 열어 확인하세요. 새 연결이나 복구는 [모바일만 복구하기](#모바일만-복구하기)를 따르세요. |
| `mobileStatus: needs-action` | `mobileError`를 확인하고 `mobileRetryCommand`를 실행하세요. [모바일만 복구하기](#모바일만-복구하기) |
| `mcpStatus: needs-action` | `mcpError`를 확인하고 `mcpRetryCommand`를 실행하세요. PC 앱은 `desktopUrl`에서 열 수 있습니다. [MCP만 복구하기](#mcp만-복구하기) |

## 연결 복구

이미 설치한 **VIV 폴더**에서 실행하세요. 서버가 저장한 포트를 사용합니다. 새 설치에서 기본 포트가 사용 중이면 설치 결과의 새 주소를 여세요. 기존 주소나 직접 지정한 포트가 다른 프로그램과 충돌하면 설치기가 포트와 복구 방법을 표시합니다. 포트를 저장하기 전 버전으로 설치했다면 PC의 기존 VIV 주소에서 포트를 확인한 뒤 [서버 다시 시작](#서버-다시-시작)의 기존 설치 안내를 먼저 따르세요.

### 모바일만 복구하기

PC의 **휴대폰 연결·설치** 화면에 표시된 상태를 확인하세요.

- **저장한 주소에 연결할 수 없음**. PC의 VIV 서버와 Tailscale 연결을 확인한 뒤 **연결 다시 확인**을 누르세요. 이전 주소는 마지막 확인 시각과 함께 표시됩니다. **설치 주소 복사**는 현재 연결 확인에 성공하면 활성화됩니다.
- **공개 Funnel이 켜져 있음**. VIV에 사용할 공개 Funnel을 끄고 원래 VIV PC 주소를 가리키는 비공개 Serve 경로를 확인하세요.
- **휴대폰 주소가 이 VIV 설치와 일치하지 않음**. 원래 VIV PC 주소를 열고 Tailscale의 Serve 대상이 그 주소를 가리키는지 확인하세요. 연결을 바로잡은 뒤 **연결 다시 확인**을 누르세요.
- **이 서버에서는 휴대폰 주소를 확인할 수 없음**. 기존 휴대폰 접속 주소를 서버 관리자에게 확인하세요.
- **이 PC에서 휴대폰 연결 준비 필요**. PC에서 Tailscale 로그인이나 VPN 승인을 마친 뒤 아래 복구 명령을 실행하세요.

설치 결과의 `mobileRetryCommand`를 사용하거나, **이 PC에서 다시 실행할 명령 → 복구 명령 복사**를 누르세요. 터미널에서 실행할 때는 원래 VIV 설치 폴더에서 아래와 같이 실행합니다.

**Windows**

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\setup-self-host.ps1 -MobileOnly
```

**Mac**

```bash
bash scripts/install-viv-mac.sh --mobile-only
```

터미널에서 `mobileStatus: phone-install-pending`을 확인했다면, 브라우저에서 뒤로 돌아가 PC의 설치 화면에서 **연결 다시 확인 → 설치 주소 복사**를 누르세요. 복사한 주소 또는 설치 결과의 `mobileInstallUrl`을 같은 Tailscale 네트워크의 휴대폰에서 여세요.

### MCP만 복구하기

휴대폰에서 시작했다면 **설정 → 서비스 연결 → AI 연결·복구 (MCP)**에서 **PC에서 이어갈 주소 복사**를 누르고, 그 주소를 VIV가 설치된 컴퓨터의 브라우저에 붙여 넣으세요. PC에서 같은 설치가 확인되면 MCP 주소와 연결 명령이 열립니다. PC 주소를 가져오지 못하면 **PC 주소 다시 확인**을 누르거나 설치 때 받은 **VIV PC** 주소를 사용하세요.

먼저 PC 주소에서 VIV를 열고 **설정 → 서비스 연결**에서 **AI 연결·복구 (MCP)** 버튼을 누르세요. **MCP 주소 복사**로 현재 주소를 가져오거나 **Codex·Claude Code 연결 명령**을 펼쳐 사용하는 클라이언트의 명령을 실행하세요. 설치 결과에 `mcpRetryCommand`가 있다면 같은 작업을 수행합니다. 아래 명령은 앱 화면에서 복구 명령을 찾기 어려울 때 사용할 수 있습니다.

**Windows**

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\setup-self-host.ps1 -StartOnly -Client Codex
```

**Mac**

```bash
bash scripts/install-viv-mac.sh --target pc --client codex
```

Claude Code는 Windows에서 `-Client Claude`, Mac에서 `--client claude`를 사용하세요. 등록에 성공하면 결과의 `onboardingPrompt` 또는 MCP 전용 명령의 `startMessage`를 AI의 새 대화에 입력하세요. `viv`가 다른 주소에 등록돼 있으면 설치기가 새 이름을 선택합니다. 예를 들어 새 이름이 `viv-4499`이면 **viv-4499 도구로 VIV 시작하기**를 입력합니다.

수동 연결은 앱에서 복사한 MCP 주소 전체를 등록하세요. 주소의 `installation` 값은 해당 설치를 확인합니다. 예전에 등록한 `/mcp` 주소는 포트가 가리키는 서버에 연결되므로 설치가 여러 개일 때는 각 앱에서 복사한 주소로 등록하세요. [MCP와 첫 대화](viv-mcp-playbook.md#연결)

## 앱 열기와 조회 복구

이전에 VIV를 정상적으로 열었던 브라우저에서 **VIV 서버에 연결할 수 없어요**가 보이면 화면에 표시된 인터넷 또는 PC 서버 확인부터 진행하세요. PC에서는 VIV가 열리면 **모바일 연결 복구 안내**를 따르세요. PC 주소도 열리지 않으면 **서버 다시 시작**을 펼쳐 설치한 컴퓨터에서 명령을 실행하세요. 연결을 복구한 뒤 **다시 연결**을 누르면 보고 있던 주소로 돌아갑니다.

휴대폰에서 처음 열어 브라우저의 기본 오류나 **502 / Bad Gateway**가 보이면 인터넷과 Tailscale 연결을 먼저 확인하세요. PC에서는 VIV가 열리면 [모바일만 복구하기](#모바일만-복구하기)를, PC에서도 열리지 않으면 [서버 다시 시작](#서버-다시-시작)을 따르세요. 연결이 돌아오면 원래 휴대폰 탭에서 새로고침하세요.

현재 화면에 표시된 버튼부터 사용하세요.

| 보이는 화면 | 다음 행동 |
| --- | --- |
| 휴대폰 연결·설치 안내 | **VIV 서버 응답 확인** 뒤 **VIV 열기**를 누릅니다. **접근이 거부되었습니다**가 나오면 휴대폰이 PC와 같은 Tailscale 네트워크에 로그인했는지 확인하세요. **VIV 서버 연결을 확인할 수 없습니다**가 나오면 PC에서 기존 **VIV PC** 주소를 열어 보세요. PC에서 열리면 **모바일 연결 복구 안내**를 따라 복구한 뒤 휴대폰에서 **연결 다시 확인**을 누르세요. |
| **이 주소에서 VIV 서버 응답을 확인할 수 없습니다** | PC의 **설정 → 서비스 연결 → 휴대폰 연결·설치**에서 현재 설치 주소를 확인하고, 휴대폰에서 원래 VIV 주소를 다시 여세요. |
| **VIV를 시작하지 못했습니다.** | **다시 열기**를 한 번 누릅니다. 같은 화면으로 돌아오거나 **앱 파일을 불러올 수 없습니다**가 표시되면 [시작 오류가 반복될 때](#시작-오류가-반복될-때)를 따르세요. |
| 시작 화면에서 **VIV 연결·시작 문제 해결**만 열 수 있음 | [시작 오류가 반복될 때](#시작-오류가-반복될-때)에서 PC의 앱 파일을 확인하세요. |
| **VIV를 열려면 브라우저에서 JavaScript를 켜세요.** | 브라우저의 이 사이트 설정에서 JavaScript를 허용하고 원래 주소를 새로고침하세요. |
| 앱 주소에 **404** 또는 **Not found**만 표시 | [시작 오류가 반복될 때](#시작-오류가-반복될-때)에서 빠진 앱 파일을 확인하세요. |
| 앱 안의 **워크스페이스 연결** 또는 캘린더의 조회 오류 | **다시 조회**를 누릅니다. 서버가 응답하면 같은 주소에서 저장 기록을 이어서 볼 수 있습니다. |

PC에서 기존 **VIV PC** 주소에 접속할 수 없으면 [서버 다시 시작](#서버-다시-시작)을 사용하세요. PC에서 앱이 열리고 휴대폰 브라우저에서 서버에 연결할 수 없으면 [모바일만 복구하기](#모바일만-복구하기)를 따르세요.

### 시작 오류가 반복될 때

휴대폰 설치 화면에서 **설치 화면 다시 확인**, 앱 시작 화면에서 **다시 열기**를 누르세요. 같은 오류가 반복되면 **확인할 앱 파일**에 표시된 경로와 응답을 확인하세요.

| 화면이나 네트워크 탭에 표시된 응답 | 다음 행동 |
| --- | --- |
| **HTTP 404**와 `dist/…` 파일 경로 | 아래 명령으로 PC 설치 폴더에 그 파일이 빠졌는지 확인하세요. |
| 파일 요청에 **HTML 응답**, 또는 **HTTP 200 · text/html** | 원래 VIV PC 주소에서 같은 파일 요청을 비교하세요. 아래의 **파일 응답 비교**를 따르세요. |
| **접근이 거부되었습니다** 또는 **HTTP 401·403** | 휴대폰이 설치한 PC와 같은 Tailscale 네트워크에 로그인했는지 확인하세요. [모바일만 복구하기](#모바일만-복구하기) |
| **연결 경로가 VIV 서버에 닿지 않습니다**, **응답 시간 초과**, 또는 **파일 전송을 완료하지 못함** | 원래 VIV PC 주소를 확인하세요. PC에서 열리면 [모바일만 복구하기](#모바일만-복구하기), PC에서도 열리지 않으면 [서버 다시 시작](#서버-다시-시작)을 따르세요. |

**VIV를 열려면 브라우저에서 JavaScript를 켜세요**가 보이면 브라우저의 이 사이트 설정에서 JavaScript를 허용한 뒤 원래 주소를 새로고침하세요.

1. **휴대폰 홈 화면 아이콘에서 멈추면** 설치에 사용한 같은 주소를 Safari 또는 Chrome에서 직접 여세요. 설치 안내가 표시되면 **VIV 열기**를 누릅니다. 앱이 열리면 그 창에서 기존 작업을 이어가세요.
2. **빠진 파일을 확인하고 복원하려면** VIV를 설치한 PC의 원래 설치 폴더에서 누락 목록을 확인하세요.

   ```sh
   git ls-files --deleted -- dist
   ```

   오류 화면과 누락 목록에 **같은 경로**가 있을 때 해당 파일 하나를 복원하세요.

   **설치 화면에서 `dist/ui/install-page.mjs`가 빠진 경우**

   ```sh
   git --literal-pathspecs restore --worktree -- "dist/ui/install-page.mjs"
   ```

   **앱 시작 화면에서 `dist/app.mjs`가 빠진 경우**

   ```sh
   git --literal-pathspecs restore --worktree -- "dist/app.mjs"
   ```

   다른 파일이면 위 명령의 따옴표 안을 두 곳에 공통으로 표시된 파일 경로로 바꾸세요. 목록이 비어 있거나 해당 경로가 없으면 3단계에서 응답을 확인하세요.

   복원 후 같은 목록 명령을 다시 실행해 해당 경로가 사라졌는지 확인하세요. 원래 탭에서 **설치 화면 다시 확인** 또는 **다시 열기**를 누르세요. 도움말을 같은 탭에서 열었다면 브라우저의 **뒤로**를 먼저 누르세요. 설치 안내가 돌아오면 **VIV 열기**를 누르세요.
3. **파일 응답 비교**. PC의 Edge 또는 Chrome에서 **개발자 도구 → 네트워크**를 열고 문제가 난 주소를 새로고침하세요. 오류 화면의 파일 요청을 선택해 상태 코드와 `Content-Type`을 확인하세요. 경로가 표시되지 않으면 **콘솔**의 첫 모듈 오류에서 파일 이름을 찾으세요.

   원래 **VIV PC** 주소에서도 같은 파일을 열어 보세요. 파일 경로의 `dist/`를 빼고 주소 뒤에 붙입니다. 예를 들어 `dist/ui/install-page.mjs`는 `http://127.0.0.1:4317/ui/install-page.mjs`처럼 확인합니다. 포트는 설치할 때 받은 PC 주소의 값을 사용하세요. PC 주소에서 JavaScript가 응답하고 문제 주소에서 HTML이 응답하면 접속 경로의 프록시나 웹 서버를 확인하세요. 두 주소에서 HTML이 응답하면 PC 서버의 파일 요청부터 확인하세요.

   접속 경로를 고친 뒤 원래 탭에서 **설치 화면 다시 확인** 또는 **다시 열기**를 누르세요. 버튼이 없으면 주소 전체를 새로고침하세요. 같은 오류가 계속되면 **네트워크 → 캐시 사용 중지**를 선택하고 개발자 도구를 열어 둔 채 새로고침하세요. 그동안 같은 설치의 **VIV PC** 주소 뒤에 원래 주소의 `#`부터 끝까지 붙이면 기존 날짜나 보고서를 열 수 있습니다.
4. **원래 PC 주소와 접속 경로에서 같은 오류가 나면** PC에서 오류가 난 주소 전체를 복사해 새 비공개 창(Edge InPrivate, Chrome 시크릿 창, Safari 개인정보 보호 윈도우)에서 열어 보세요. VIV의 저장 기록은 서버에 있으며 브라우저 탭에 임시로 적던 내용은 새 창에서 이어지지 않을 수 있습니다.
5. **두 창에서 모두 시작 오류가 반복되면** 아래 정보를 앱 관리자에게 전달하세요.

   - 원래 설치 폴더에서 `git rev-parse --short HEAD`로 설치 버전, `git status --short -- dist`로 앱 파일 변경 여부를 확인하세요.
   - PC 브라우저에서 새로고침한 뒤 **콘솔**의 첫 JavaScript 오류와 파일을 `Error · session-storage.mjs:1`처럼 적으세요. **네트워크**의 파일 요청 결과는 `HTTP 200 · text/html · /app.mjs` 또는 `HTTP 404 · /ui/studio-controller.mjs`처럼 적습니다.
   - 운영체제와 브라우저, 비공개 창에서의 결과를 함께 적으세요. [VIV 문제 목록](https://github.com/HwigwanJi/viv/issues)에서 같은 증상을 찾아볼 수 있습니다. 공개 글에는 오류를 요약하고 API 키, 계좌 정보, 비공개 접속 주소는 가려 주세요.

저장한 실험과 완료 보고서를 다시 여는 방법은 [캘린더에서 백테스트 이어가기](viv-mcp-playbook.md#캘린더에서-백테스트-이어가기)를 참고하세요.

## 서버 다시 시작

VIV 서버가 꺼져 있으면 **설치했던 VIV 폴더**에서 다음 명령을 실행하세요. 저장한 포트와 기록을 그대로 사용합니다. 다시 시작한 뒤 [열려 있는 화면의 버튼](#앱-열기와-조회-복구)을 누르거나 터미널의 **VIV PC** 주소를 여세요.

**Windows**

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\install-viv.ps1 -Resume
```

**Mac**

```bash
bash scripts/install-viv-mac.sh --resume
```

기존 AI에서 **VIV 시작하기**를 입력하거나 휴대폰의 기존 VIV 아이콘을 여세요. 열리지 않는 연결만 [복구](#연결-복구)하세요. `.env`를 수정했다면 현재 VIV 서버를 먼저 종료한 뒤 위 명령을 실행해야 변경 사항이 적용됩니다. `serverPid`가 비어 있다면 **VIV PC** 주소의 포트로 Windows `Get-NetTCPConnection -LocalPort <포트> -State Listen` 또는 Mac `lsof -nP -iTCP:<포트> -sTCP:LISTEN`에서 확인할 수 있습니다. 종료 전에 해당 프로세스가 이 폴더의 VIV인지 확인하세요.

포트를 저장하기 전 버전에서 설치했다면 원래 VIV 폴더에서 `git pull --ff-only`로 업데이트한 뒤 기존 PC 주소의 포트를 한 번 전달하세요. 아래 `4317`을 기존 주소의 포트로 바꿔 실행합니다.

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\setup-self-host.ps1 -StartOnly -Client Manual -Port 4317
```

```bash
bash scripts/install-viv-mac.sh --target pc --client manual --port 4317
```

이후 위 재실행 명령을 사용하세요. 주소가 다른 설치나 서비스에 속한다는 오류가 나오면 기존 VIV 주소와 포트를 점유한 프로그램을 확인하세요. 해당 프로그램에서 포트를 해제한 뒤 같은 명령을 다시 실행하세요.

VIV의 MCP 등록을 제거하려면 해당 연결의 `mcpName`을 확인하고 Codex에서 `codex mcp remove <이름>`, Claude Code에서 `claude mcp remove <이름> --scope user`를 실행하세요.

## 기존 기록 복원

새 폴더로 기존 VIV 기록을 옮길 때는 원래 서버를 완전히 종료하고, 그 설치 또는 같은 백업에서 `.runtime/self-host.sqlite`와 숨김 파일 `.env`를 함께 가져오세요. 새 VIV 폴더의 `.runtime` 안에 DB를, VIV 폴더 바로 아래에 `.env`를 둡니다. 같은 원본에 `.runtime/self-host.sqlite-wal`이 남아 있으면 최신 기록을 보존할 수 있도록 그 파일도 DB 옆에 둡니다. 원래 `.env`의 키로 저장된 계좌 연결을 읽습니다. 이 파일은 로컬에서만 옮기고 채팅이나 Git에 올리지 마세요. [SQLite WAL 안내](https://sqlite.org/wal.html#the_wal_file)

설치가 원래 `.env`를 요청하면 터미널에 표시된 VIV 폴더에 그 파일을 복원하고 같은 명령을 다시 실행하세요.

### 같은 폴더에서 다시 시작

[서버 다시 시작](#서버-다시-시작)을 실행한 뒤 기존 **VIV PC** 주소와 기존 AI 연결 이름을 사용하세요.

### 새 폴더에 복원한 뒤 AI에서 기록 열기

1. 새 폴더에서 [Windows 설치](#windows-서버와-휴대폰) 또는 [Mac 설치](#mac-서버와-휴대폰)를 실행하세요. 터미널에 표시된 **VIV PC** 주소에서 **모의 → 마인드 → 전체 기록**을 열어 옮긴 기록을 확인합니다.
2. 새 폴더에는 별도의 MCP 주소가 생깁니다. 설치 결과가 `registered`라면 결과에 표시된 `mcpName`을 사용하세요. AI를 수동으로 연결하거나 예전 설치가 열린다면 새 **VIV PC** 주소에서 **설정 → 서비스 연결**을 열고 **AI 연결·복구 (MCP)** 버튼을 누르세요. 해당 클라이언트의 명령을 실행하거나 새 MCP 주소 전체를 복사해 등록하세요. 기존 연결은 등록된 이름으로 계속 열 수 있습니다. [MCP만 복구하기](#mcp만-복구하기)
3. AI의 새 대화에 “**[설치 결과의 MCP 이름] 도구로 복원한 최근 모의 판단의 이유와 체결 건수를 알려주고, 저장된 기록 링크를 열어줘**”라고 입력하세요. 링크에서 해당 행의 **상세**를 열면 앱에서 확인한 같은 판단을 볼 수 있습니다. 최근 목록에 없는 판단은 **모의 → 마인드 → 전체 기록**에서 날짜, 종목 또는 마인드로 찾으세요. 화면에 표시된 한국 날짜를 사용하세요. 날짜와 종목을 함께 넣어 좁힐 수도 있습니다. 예를 들어 `2026-11-12 BTC-USDT`로 검색합니다. 해당 행의 **상세 → 이 판단을 기록에서 보기**에서 개별 기록 링크를 열어 AI에 전달할 수 있습니다.

## 자기 API 키와 계좌

| 필요한 기능 | 설치 후 설정 |
| --- | --- |
| 앱·퀀트 편집·연구 | 자체 SQLite를 사용한다. 설치 자체에는 공급자 키가 필요 없다. |
| AI/JEV | JEV를 호출하는 판단·분류·추천에 필요합니다. [TypeSafe 콘솔](https://console.typesafe.ai/keys)에서 본인 키를 발급하고, VIV 서버가 실행되는 컴퓨터의 설치 폴더에서 `.env`에 `TYPESAFE_API_KEY`를 설정합니다. [서버를 다시 시작](#서버-다시-시작)한 뒤 앱의 **설정 → 서비스 연결 → 상태 새로고침**을 누르세요. **서버 설정 확인**은 서버가 설정값을 읽었다는 뜻입니다. 원래 화면으로 돌아가 요청한 작업을 실행하면 키 유효성을 확인할 수 있습니다. 키 없이 시작하려면 [과거 시세 퀀트 실습](viv-mcp-playbook.md#첫-모의-실습)을 이용하세요. |
| 업비트·토스증권 계좌 | [계좌 연결과 잔고 확인](#계좌-연결과-잔고-확인)을 따릅니다. |
| KIS 읽기 시세 | 사용하는 경우 자신의 `KIS_APP_KEY`, `KIS_APP_SECRET`, `KIS_ACCESS_TOKEN`을 로컬 환경에 설정한다. |

첫 실행에서 `.env`가 없으면 설치별 `BROKER_VAULT_KEY`를 파일에 생성한다. 이후 그 파일과 DB를 함께 개인 백업한다. 공유 저장소에는 앱 소스·잠금 파일·설치 스크립트를 올리고, 실제 `.env`·DB·계좌 기록·Tailscale 주소가 들어간 생성 파일·APK 서명 키는 개인 보관한다. 새 서버에서 실전 운용이 필요하면 별도로 관리형 실행 환경을 구성하고 앱에서 본인의 계좌·자금·한도를 승인한다.

## 계좌 연결과 잔고 확인

이 화면에서 연결하는 계좌의 용도는 잔고 조회입니다. 첫 모의 판단 중 **화면 찾기**에서 연결 화면을 열었다면 **진행하던 모의 판단으로 돌아가기**를 눌러 같은 마인드와 종목에서 이어가세요. 튜토리얼의 저장 결과에서 연결 화면을 열었다면 **저장한 모의 결과로 돌아가기**를 누르세요. 계좌·자금 화면을 바로 열었다면 **모의 홈으로**에서 연습을 이어갈 수 있습니다.

1. 상단의 **화면 찾기**에서 **실계좌 API 키 등록**을 검색하거나 **실전 → 작업 공간 메뉴 → 설정 → 계좌·자금**으로 이동하세요. 처음 연결한다면 금융기관 카드에서 **연결 준비 보기** 또는 **계좌 연결**을 누르세요. 이미 연결한 계좌는 **연결 정보 변경**에서 엽니다.
2. 새 키는 PC 웹에서 발급하세요. 휴대폰 연결 창에서 **PC 연결 주소 복사**를 누르고 PC 브라우저에 붙여 넣으세요. 같은 금융기관의 연결 창이 열립니다. PC에서도 진행하던 모의 판단이나 저장한 모의 결과로 돌아갈 수 있습니다. VIV 서버 설정이 준비되어 있으면 키 입력창이 표시됩니다. PC에서 주소가 열리지 않으면 설치 결과에 표시된 **VIV PC** 주소에서 **계좌·자금**을 여세요.
3. 업비트는 PC 웹의 **Open API 관리**에서 **자산조회** 권한만 선택하세요. VIV 서버의 **공인 발신 IPv4**를 허용 목록에 입력하고 2채널 인증으로 발급을 마치세요. 휴대폰의 Tailscale 주소는 VIV 앱에 접속할 때 씁니다. 별도 서버나 VPN을 쓰면 VIV 서버가 업비트로 요청을 보내는 경로의 주소를 확인하세요. [업비트 키 발급 절차](https://docs.upbit.com/kr/docs/api-key) 토스증권은 PC 웹의 **설정 → Open API**에서 발급하고 같은 메뉴의 **허용 IP 관리**에서 서버 IP를 등록하세요. [토스증권 Open API 가이드](https://developers.tossinvest.com/)
4. **서버 허용 IP 준비 필요**가 표시되면 허용 IP를 등록한 뒤 VIV 설치 폴더의 `.env`에 `BROKER_NETWORK_READY=true`를 설정하세요. `BROKER_EGRESS_IP`는 서버 IP를 앱에 표시할 때 쓰는 선택 항목입니다. [서버를 다시 시작](#서버-다시-시작)하고 **준비 상태 다시 확인**을 누르세요. 이 버튼은 VIV 서버 설정을 읽습니다. 금융기관의 허용 IP와 키 권한은 다음 단계에서 확인합니다.
5. VIV 연결 창에 업비트의 **Access Key·Secret Key** 또는 토스증권의 **Client ID·Client Secret**을 입력하고 **연결하고 잔고 조회**를 누르세요. 키는 이 창에만 입력하세요. 해당 카드에 이번에 조회한 시각과 잔고가 표시되면 조회가 완료된 것입니다.

| 화면에서 확인한 상태 | 다음 행동 |
| --- | --- |
| 서버 허용 IP 준비 필요 | 원래 설치 폴더의 `.env`를 수정했는지 확인하세요. 실행 중이던 VIV 서버를 종료한 뒤 다시 시작하고 준비 상태를 확인하세요. |
| 서버 키 보관 설정 필요 | 이 설치에서 사용하던 `BROKER_VAULT_KEY` 설정을 확인하세요. 기존 계좌가 있는 설치는 원래 `.env`의 키를 사용합니다. |
| 서버 응답을 확인하지 못함 | 서버가 다시 열리면 복사한 **PC 연결 주소**를 열거나, 연결 창의 **준비 상태 다시 확인**을 누르세요. |
| 업비트 허용 IP 오류 | 업비트 **Open API 관리**에서 해당 키의 허용 IP를 현재 VIV 서버의 공인 발신 IPv4로 수정하고, VIV의 연결 창에서 다시 조회하세요. |
| 업비트 자산조회 권한 오류 | **자산조회** 권한으로 발급한 키를 같은 창에 입력하세요. [업비트 포켓 잔고 조회 권한](https://docs.upbit.com/kr/reference/get-balance) |
| 연결 결과를 확인할 수 없음 | 창을 닫고 카드의 **저장 조회** 시각을 확인하세요. 이전 조회 시각이면 카드에서 확인할 수 있는 정보도 이전 결과입니다. |

별도 Android APK가 필요한 경우에는 [APK 빌드 가이드](../../../android/README.md)를 사용한다. Windows 설치 명령의 기본 휴대폰 경로는 같은 앱을 설치하는 웹앱이다.
