# VIV MCP 설치와 첫 대화

설치 에이전트에게 이렇게 요청할 수 있습니다.

> 이 저장소의 VIV를 Windows에 원샷으로 설치해 줘. 사용할 환경을 먼저 물어보고, 내 선택에 맞춰 앱·서버·MCP를 설치하고 확인해 줘.

## 연결

새 PC에서는 [VIV 설치](self-host.md)를 먼저 실행하세요. 이미 VIV가 열리면 운영체제에 맞는 [MCP만 복구하기](self-host.md#mcp만-복구하기) 명령을 사용하세요. Claude Code는 사용자 범위에서 연결을 확인합니다. 새 폴더로 기존 데이터를 옮겼다면 [복원한 기록을 AI에서 열기](self-host.md#새-폴더에-복원한-뒤-ai에서-기록-열기)를 따르세요.

수동 연결은 VIV의 **설정 → 서비스 연결**에서 **AI 연결·복구 (MCP)** 버튼을 누르고 **MCP 주소 복사**를 사용하세요. 설치한 포트에 맞는 주소가 표시됩니다. AI 클라이언트와 VIV 서버가 같은 컴퓨터에서 실행될 때 쓸 수 있습니다.

1. `initialize`에서 `viv`, `tools/list`에서 `viv_onboarding`을 확인합니다.
2. MCP를 현재 대화에서 쓸 수 있으면 해당 설치의 `viv_onboarding`을 호출해 바로 시작합니다. 연결을 다시 읽어야 하는 클라이언트에서는 설치 결과의 `onboardingPrompt`를 새 AI 대화에 입력하거나 해당 설치의 MCP 프롬프트 메뉴에서 **VIV 시작하기**를 선택합니다.
3. 링크를 열 수 있는 AI 앱에서는 VIV의 결과를 인앱 브라우저에 띄웁니다. 앱이 인앱 브라우저를 제공하지 않으면 같은 결과 링크를 누를 수 있게 표시합니다. 휴대폰에서 보려면 같은 tailnet에서 서버의 비공개 HTTPS 주소를 엽니다.

이 연결은 Claude Code가 실행 중인 PC의 VIV를 사용합니다. Claude 웹·모바일의 원격 커넥터는 Anthropic 서버에서 연결하므로 PC의 루프백 주소를 사용할 수 없습니다. [Claude Code MCP](https://code.claude.com/docs/en/mcp) · [Claude 원격 커넥터](https://support.claude.com/en/articles/11175166-get-started-with-custom-connectors-using-remote-mcp)

## 기본 프리셋으로 시작하기

새 설치에는 **추세형**, **역발상형**, **장기보유형** 마인드가 들어 있습니다. 새 마인드를 만들 때는 **모의 → 마인드 → 마인드 추가 → 시작 전략**에서 기본 프리셋을 선택할 수 있습니다.

| 시작 전략 | 확인할 내용 |
| --- | --- |
| 국면 학습 · 현금과 다종목 배분 | 시장 상태에 따라 여러 업비트 원화 종목과 현금의 목표 비중을 조정합니다. |
| 급등 후 눌림 P50 · 분할익절 | 업비트 원화 종목의 급등 후 눌림 조건과 분할익절 규칙을 사용합니다. |
| 국면 추세 | BTC-USDT 4시간봉과 장기 이동평균을 쓰는 전략입니다. 아래 백테스트를 AI 호출 없이 실행할 수 있습니다. |
| 단기 순환 · 목표 6% | 여러 코인 중 강한 두 종목을 고릅니다. 계좌 순수익률 6% 또는 운용 5일을 종료 조건으로 사용합니다. |
| 장기 모멘텀 | 상승 추세와 상대 모멘텀을 기준으로 종목을 주 단위로 재배분합니다. |
| 하락장 반등 | 하락장 반등 조건에서 퀀트와 JEV 판단을 결합합니다. JEV 호출이 필요한 실험은 키와 호출 동의를 요청합니다. |

**직접 구성**을 고르면 투자 원칙과 근거를 입력하고 전략 노드를 별도로 구성합니다. 프리셋을 고르면 기본 이름과 투자 범위를 확인하고 바로 초안을 저장할 수 있습니다. 바꾸고 싶은 항목은 **이름과 원칙 편집 (선택)**을 열어 입력하세요. 빈 항목에는 프리셋 기본값이 적용됩니다. 자동 운용은 별도 설정에서 시작합니다.

1. **국면 추세**를 선택하고 **마인드 생성**을 누릅니다. **전략 정책 검토**에서 투자 범위와 실행 주기를 확인합니다. **검토·발행**을 눌러 검토 이유를 적고 **검토 후 발행**을 누릅니다. 창을 닫았다면 해당 마인드의 **전략 → 검토 중 정책 → 정책 검토**에서 이어갑니다.
2. 새 마인드의 **전략** 화면에서 발행 버전을 확인합니다. **실험실 → 새 실험 → 백테스트 → 계속**을 누르고, 검증 대상이 방금 만든 마인드이고 실행 방식이 **마인드 전략**인지 확인합니다.
3. **기간 선택 → 실행 검토**에서 보관 가격 범위, 적용 정책 버전, 비용, **예상 최대 AI 호출 0회**를 확인합니다. 이 예제는 OKX BTC-USDT 정책을 Binance BTCUSDT 보관 시세로 검증합니다. 다른 프리셋은 실험 화면에서 필요한 종목·기간의 자료를 확인하세요. 필요하면 **상세 설정**에서 초기 자금과 비용을 바꿉니다. 자료가 부족하면 **기간 변경**, 조회가 끊기면 **실행 조건 다시 확인**으로 이어갑니다. **저장하고 실행 준비 → 실행**을 누릅니다.
4. **완료**가 표시되면 **성과·비교**에서 순수익률과 최대 낙폭을 보고, **보고서·원본**에서 실행한 전략의 버전과 원본 식별값을 확인합니다. 나중에는 모의 홈의 **최근 완료 실험**이나 해당 마인드의 **실험실**에서 같은 결과를 다시 엽니다.

홈의 **첫 백테스트 실습**은 공통 BTC 기준 퀀트 전략을 실행합니다. 방금 발행한 프리셋을 시험하려면 위의 **마인드 전략**을 선택하세요.

## 첫 모의 실습

보관한 BTC 과거 시세로 백테스트를 실행하고, 어떤 판단이 나왔는지 확인한 뒤 같은 결과를 다시 열어 봅니다. AI 연결이나 모의 예산 없이 앱에서 시작할 수 있습니다.

1. 터미널의 **VIV PC** 주소 또는 설치 결과의 `desktopUrl`을 여세요. 설치 화면에서는 **VIV 열기**를 누르세요. 상단에서 **모의**를 선택한 뒤 **홈 → 첫 백테스트 실습**을 엽니다. 홈에 **첫 백테스트 실습**이 보이지 않으면 **화면 찾기**에서 같은 이름으로 검색해 새 실습을 여세요. **백테스트 이어하기**는 전에 저장한 실험을 엽니다.
2. 예제로 **추세형**을 고르고 **기간 선택**을 누르세요. 처음에는 화면에 제시된 기간으로 **실행 검토**를 누르세요. 기간을 바꾸려면 그래프에 표시된 보관 시세 범위 안에서 시작·종료 시각을 UTC로 입력하고 **기간 적용**을 누르세요. **실행 검토**에서 초기 자금과 비용, **예상 최대 AI 호출** 0회를 확인하세요. 초기 자금과 비용을 바꾸려면 **상세 설정**을 여세요. 조회가 끊기면 **실행 조건 다시 확인**을 누르세요.
3. **저장하고 실행 준비**를 누르면 실험 조건이 저장됩니다. 같은 화면의 **실행**을 누르면 계산을 시작합니다. 나중에 실행하려면 [캘린더에서 백테스트 이어가기](#캘린더에서-백테스트-이어가기)를 따르세요.
4. **완료**가 표시되면 **성과·비교**에서 순수익률과 최대 낙폭을 확인하세요. 상단에는 **AI 호출 0회**가 표시됩니다. **판단**에서 원하는 행의 **상세**를 열면 시세 기준 봉, 판단 근거와 모의 실행을 볼 수 있습니다. 저장된 판단 데이터는 상세 창의 **호출 원문**에서 **저장된 결정 원본**을 펼쳐 확인하세요. 상세 조회가 실패하면 같은 창에서 **다시 조회**를 누르세요.
5. 모의 **홈**의 **최근 완료 실험**을 열고 **보고서·원본**을 선택하세요. **저장 상태**가 **전체 기간 완료**인지 확인하세요. 조회가 실패하면 **다시 조회**를 눌러 같은 보고서를 여세요. 다른 실험을 열려면 모의 홈의 **전체 시뮬레이션**에서 **실험 이름 검색**을 사용하세요. 이름이 같으면 각 항목의 **테스트 기간(KST)**과 **상태**를 대조한 뒤 이름을 눌러 여세요.

### 캘린더에서 백테스트 이어가기

현재 시세로 저장한 판단을 찾으려면 [캘린더에서 모의 판단 확인하기](#캘린더에서-모의-판단-확인하기)로 이동하세요. 같은 탭에서는 새로고침 후에도 **캘린더** 메뉴나 **화면 찾기 → 캘린더**에서 마지막으로 본 월·날짜를 이어서 볼 수 있습니다. 현재 날짜로 이동하려면 캘린더의 **오늘**을 누르세요.

1. **캘린더 → 모의검증 현황**에서 **실행 대기**가 표시된 실험의 이름을 누르세요. 찾는 실험이 더 아래에 있으면 **전체 N건 보기**로 목록을 펼치세요. 이름이 같으면 항목의 **테스트 기간**을 확인하세요. 테스트 기간은 검증에 사용할 과거 시세 범위입니다. 월을 바꿔도 저장한 실행 대기 항목은 현황에서 볼 수 있습니다.
2. 저장한 기간, 초기 자금과 비용을 확인하고 **실행**을 누르세요. **일시중지**한 실험은 같은 현황에서 열고 **이어서 실행**을 누르세요.
3. 기준 퀀트 전략의 단독 백테스트를 마쳤다면 보고서의 **캘린더에서 완료 날짜 보기**를 누르세요. **캘린더** 메뉴에서 실행을 마친 날짜를 직접 선택할 수도 있습니다. 해당 날짜의 **과거 시세 검증 완료** 항목을 열고, 이름이 같으면 **테스트 기간**과 완료 시각을 대조하세요. **보고서·원본 → 보고서 ID**에서 원하는 실험인지 확인합니다. 기준 퀀트 보고서에 완료 시각이 저장되지 않았다면 **캘린더에서 결과 날짜 보기**로 결과 갱신 날짜를 열 수 있습니다. 날짜와 시각은 한국 시간 기준입니다.
4. 캘린더나 보고서 조회에 실패하면 해당 화면의 **다시 조회**를 누르세요. 선택한 월·날짜나 같은 보고서를 다시 불러옵니다.

- **완료 항목의 수익률**은 테스트 기간 전체의 성과입니다. 전략 비교의 **B 수익률**은 비교 전략 B의 성과이고, 전략 튜닝의 **검증 수익률**은 선택한 후보의 검증 구간 성과입니다. 전체 구간을 평가할 자료가 부족해 수익률이 비어 있으면 보고서를 열어 평가 범위를 확인하세요.
- **모의 실현 손익**은 선택한 날의 모의 매도로 확정된 금액입니다. 통화별로 표시하며 합계가 정확히 0이면 **0**이 표시됩니다. **실현 손익 기록 없음**은 그날 집계할 모의 매도 손익이 없는 경우입니다. 월간 칸에 **미확인**이 보이면 날짜를 눌러 확인하세요. **실현 손익 미확인**은 매도 체결이 있으나 금액을 확인할 수 없는 경우이며, 일부 금액만 확인되면 **확인된 금액**으로 표시합니다. 화면 찾기에 **손익 미확인**을 입력해도 캘린더를 열 수 있습니다.

### 저장 보고서 확인하기

| 확인하려는 항목 | 화면에서 볼 곳 |
| --- | --- |
| 같은 실험인지 확인 | **보고서 ID**를 이전에 열어 둔 보고서와 대조하세요. 조건을 바꿔 새로 실행한 실험에는 새 ID가 생깁니다. |
| 실행 조건 확인 | **실험 조건**에서 **실행 조건**으로 시작하는 항목을 펼쳐 요청 기간, 초기 자금과 편도 비용을 확인하세요. **보고서·원본**의 **보고서·입력·평가 원본**을 펼치면 저장한 정책과 자료 식별값을 볼 수 있습니다. |
| 보고서 파일 보관 | **JSON 내려받기**에는 고정 입력과 판단·체결·평가 기록이 들어 있습니다. **원본 식별값**은 이 JSON 파일의 SHA-256입니다. 표 형식이 필요하면 **CSV 내려받기**를 사용하세요. |

다른 탭에서 실행을 마쳤다면 **실험 작업**의 **새로고침**을 눌러 완료 보고서를 여세요. **JSON 내려받기**는 현재 화면의 원본 식별값에 해당하는 파일을 저장합니다.

완료 결과의 **이 조건으로 다시 검증**은 새 실험의 실행 검토를 엽니다. 기간과 거래 비용, 예상 AI 호출을 확인하고 필요하면 조건을 바꾸세요. **취소하고 원본으로**는 열어 둔 결과로 돌아갑니다. **새 실험 저장**을 누르면 별도 기록을 만들며 **실행**을 누를 때 계산을 시작합니다. AI를 사용하는 경우 새 실험의 호출 상한과 동의를 입력합니다. AI 호출 시 연결한 제공사의 요금이 적용될 수 있습니다.

### 캘린더에서 모의 판단 확인하기

1. 첫 모의 판단 결과에서 **캘린더에서 판단 날짜 보기**를 누르세요. 나중에 찾을 때는 **모의 → 캘린더**에서 판단이 끝난 날짜를 한국 시간 기준으로 선택하세요. 날짜 목록에서 마인드 이름과 시각을 확인하고 **모의 판단 기록**을 누르세요.
2. 기록 상단에서 종목·마인드·시각을 확인한 뒤 **판단 근거와 체결 보기**를 누르세요. **결정 상세**에서 저장된 근거와 **모의 체결** 건수를 확인합니다. **0건**은 이 판단에 연결된 체결이 없다는 뜻입니다. **기록 확인 필요**가 표시되면 체결 건수가 아직 확인되지 않은 상태입니다. 모의 체결 응답이 끊기면 같은 판단의 저장 기록을 조회합니다. 조회도 실패하면 **이 판단 다시 조회**를 눌러 원장 상태를 확인하세요.
3. **후속 관측 기준**에 **저장됨**이 보이면 후속 관측에 사용할 시세와 모의 계좌 상태가 기록된 상태입니다. 첫 실습 결과의 **관측 기간 종료**에서 예정 시각을 확인하세요. **후속 관측 기준 검토**가 보이면 그 화면에서 기준을 저장할 수 있고, **후속 관측 상태 보기**에서 대기 상태와 필요한 자료, 결과를 확인할 수 있습니다. **확정 시세 보관 열기**가 보이면 시세를 수집하고 **원래 판단으로 돌아가기**로 관측을 이어가세요.
4. 상세 조회가 일시적으로 실패하면 **이 판단 다시 조회**를 누르세요. 기록을 찾을 수 없거나 원래 날짜로 돌아가려면 상세를 닫고 브라우저의 **뒤로**를 누르세요.

### AI 대화에서 실습 열기

이미 AI가 연결됐다면 **VIV 시작하기**를 입력하세요. 처음에는 관심 분야와 모의 원화 예산을 답합니다. 예제로 **2 코인**, **100만 원**을 선택하거나 기존 예산으로 이어가세요. **1 진행 → 4 → 키 없이 과거 데이터로 실습**을 열면 같은 백테스트 화면으로 이동합니다. 완료 후 **방금 실행한 백테스트 결과를 튜토리얼에 기록해 줘**라고 요청하면 **튜토리얼 이어하기**에서 같은 저장 보고서를 열 수 있습니다. 같은 이름의 실험이 여러 개라면 기간이나 실행 시각을 알려주세요. [연결 복구](self-host.md#연결-복구)

### 현재 확정 시세에서 모의 판단하기

앱에서 **화면 찾기 → 첫 모의 판단**을 열거나, AI 튜토리얼에서 **4 → 현재 시세로 모의 판단**을 선택하세요. 저장된 모의 판단이 없으면 **모의 홈 → 첫 모의 판단**에서도 시작할 수 있습니다. 세 경로 모두 BTC-USDT 4시간봉의 모의 트레이딩으로 이동합니다. AI가 모의 상태를 브리핑할 때도 **현재 시세로 첫 모의 판단** 링크를 열 수 있습니다. 국면 추세 프리셋은 AI/JEV 키 없이 계산합니다.

저장한 BTC-USDT 모의 판단은 **첫 모의 판단** 안내와 **설정 → 계좌·자금**의 **최근 모의 판단 보기**에서 다시 열 수 있습니다. 기록 상단에서 종목, 마인드, 시각을 확인하고 **판단 근거와 체결 보기**를 누르세요. 실습에서 기록을 열었다면 **첫 모의 판단으로 돌아가기**로 이전 실습 탭을 다시 열 수 있습니다. 여러 기록을 직접 검색할 때는 각 행의 **상세**를 사용하세요.

**모의 체결 0건**은 이 판단에 연결된 체결이 원장에 없다는 뜻입니다. **모의 체결 미확인**이 보이면 **체결 기록 다시 조회**로 같은 판단의 원장을 확인하세요. 이 버튼은 조회만 수행합니다. MCP의 `read_trading_context` 결과에서 `fillCount: null`도 미확인을 뜻합니다.

1. **첫 모의 판단**에서 화면에 보이는 항목으로 시작하세요.

   - 처음 만든다면 **국면 추세 마인드 만들기**를 누릅니다. 기본 이름과 **4시간봉 · BTC-USDT**를 확인하고 **마인드 만들고 전략 초안 저장**을 누릅니다. 이름이나 원칙을 바꾸려면 저장 전에 **이름과 원칙 편집 (선택)**을 여세요.
   - 검토 중이라면 **저장한 전략 초안 검토**를 누릅니다. 발행한 마인드가 있거나 초안이 여러 개면 **마인드 이름 · 버전 초안 검토**에서 이어갈 초안을 고릅니다.
   - 이미 발행한 버전으로 이어가려면 해당 **마인드 이름 · 발행 전략으로 시작**을 누릅니다.

   새로 만들거나 저장한 초안에서 이어가는 경우 **발행 조건 확인**을 누르세요. **검토 사유 (10자 이상)**에 확인한 종목과 적용 범위를 적고 **전략 발행**을 누르면 같은 마인드의 모의 트레이딩 화면으로 돌아옵니다. 발행 전에 창을 닫았다면 같은 탭에서 초안을 다시 열어 작성하던 사유를 이어서 입력할 수 있습니다. 판단은 트레이딩 화면에서 **결정 실행**을 누를 때 저장됩니다.

2. **USDT 모의 예산 설정**에서 총 예산을 입력하고 **예산 저장 후 배정**을 누르세요. 이미 예산을 저장했거나 중간에 나갔다면 **USDT 모의 자금 배정**에서 이어갑니다. 선택한 마인드와 배정 가능 금액을 확인하고, **금액**을 입력한 뒤 **USDT 배정**을 누르세요. 예제로 총 2,000 USDT 중 400 USDT를 배정할 수 있습니다. 원화 모의 예산은 별도로 관리됩니다.
3. **시세 수집** 또는 **시세 준비**가 보이면 **확정 시세 수집**을 누르세요. 시세가 보관되면 같은 카드의 **모의 판단 이어가기**를 눌러 선택한 마인드로 돌아갑니다. 수집이 실패하거나 대기 중이면 **과거 시세로 연습**을 열 수 있습니다. 같은 마인드가 미리 선택되고, 보관 시세와 실험용 초기 자금으로 기준 퀀트 전략을 검증합니다. **트레이딩으로 돌아가기**에서 앞서 선택한 마인드의 현재 시세 실습을 이어갑니다.
4. **결정 실행**을 누르세요. 현재 봉의 판단이 이미 저장됐다면 **저장된 결정 보기**로 같은 결과를 엽니다. 응답이 끊기거나 앱을 닫았다면 [모의 판단 이어보기](#모의-판단-이어보기)를 따르세요. **결정 상세**의 **판단에 사용한 시세**에서 당시 확정 종가와 이동평균을 확인하고, **모의 체결**에서 체결 건수를 확인하세요. **유지** 판단도 저장되며, 체결이 없으면 0건으로 표시됩니다. 다른 전략에서 **모델 응답 지표**가 표시되면 모델의 저장된 선택 확률과 확신도를 확인할 수 있습니다.
5. **이 판단을 기록에서 보기**를 누른 뒤 **판단 근거와 체결 보기**를 열면 같은 결과를 다시 볼 수 있습니다. 국면 추세 실습의 저장 결과에서 **이 마인드의 모의 트레이딩 열기**로 돌아갈 수 있습니다. 같은 봉에서 다시 열면 저장된 결과를 보여주고, 다음 판단에는 새로 확정된 시세가 필요합니다. 나중에는 모의 모드의 **마인드 → 전체 기록**에서도 찾을 수 있습니다. AI 대화에서 이어 보려면 “방금 저장된 모의 판단을 튜토리얼에 기록해 줘”라고 말하고, 다음에 **튜토리얼 이어하기**를 요청하세요. 기록만 조회하려면 “내 모의투자 상태와 최근 판단을 브리핑해줘”라고 입력하세요.

AI에 “방금 모의 판단이 왜 유지였고 체결됐어?”라고 물으면 저장된 결과를 바로 조회합니다. 호스트는 `read_investment_status`에서 대상 기록을 찾고 `read_trading_context`의 `view: result`에 해당 `decisionId`, `mindId`, `instrumentId`를 전달합니다. 확인된 판단 이유와 모의 체결 건수를 알려주고 같은 기록 링크를 엽니다. 기록 상단의 **판단 근거와 체결 보기**에서 당시 근거와 체결을 확인할 수 있습니다.

기준 퀀트 백테스트를 마쳤다면 **성과·비교 → 현재 시세 모의 판단 준비**를 여세요. 현재 발행 전략에 JEV가 필요하고 키가 없으면 **키 없이 현재 시세 연습**에서 국면 추세 마인드를 선택하거나 만들 수 있습니다. 그 마인드로 위의 USDT 모의 자금과 시세 준비를 이어갑니다. **백테스트 보고서로 돌아가기**로 처음 보고서를 다시 열 수 있습니다.

**여기까지**라고 입력하면 튜토리얼을 멈출 수 있습니다. **튜토리얼 이어하기**로 남은 항목을 다시 볼 수 있습니다.

### 모의 판단 이어보기

**결정 실행** 뒤 앱을 닫았다면, 같은 브라우저에서 원래 VIV 주소를 여세요. 설치 앱에서 실행했다면 같은 앱을 여세요. **모의**의 **홈** 또는 **마인드 목록**에서 **모의 판단 이어보기**를 누르세요. 트레이딩 화면이 열려 있다면 그 화면에서 확인을 이어가세요.

- 판단이 저장됐다면 **저장된 판단 열기**에서 근거와 체결을 확인하세요. 상세 조회가 실패하면 **이 판단 다시 조회**를 누르세요.
- 처리 중이거나 조회가 실패했다면 **저장 여부 다시 확인**을 누르세요. 이 버튼은 조회만 합니다.
- 아직 저장된 판단을 찾지 못했다면 **같은 요청 다시 실행**으로 기존 요청을 다시 보낼 수 있습니다. 마인드 설정이 바뀌었거나 새 봉이 확정됐다는 메시지가 나오면, 트레이딩에서 최신 조건을 확인한 뒤 새 판단을 실행할지 결정하세요.
- 판단을 완료하지 못했다면 **요청 기록 확인**에서 실패 이유를 확인하세요.

이어보기에는 같은 브라우저나 설치 앱에서 확인을 마치지 않은 최근 모의 판단 한 건이 표시됩니다. 링크가 없거나 다른 기기에서 열었다면, 같은 VIV에서 **모의 → 마인드 → 전체 기록**을 열고 한국 날짜와 종목으로 검색하세요. 실행 시각을 확인하고 해당 행의 **상세**를 누르세요. 날짜를 알고 있다면 [캘린더에서 모의 판단 확인하기](#캘린더에서-모의-판단-확인하기)에서도 같은 기록을 열 수 있습니다.

## 첫 대화의 순서

| 단계 | AI가 할 일 |
| --- | --- |
| 이전 결과 | 앱에서 이미 모의 판단을 저장했다면 `savedPaperDecision.openUrl`로 같은 기록을 다시 엽니다. 저장 결과를 보거나 튜토리얼을 이어갈 때는 원화 예산 입력을 건너뜁니다. |
| 모의계좌 | 원화 모의계좌를 설정할 때 1 주식 / 2 코인 / 3 둘 다와 모의 예산을 받습니다. 최초 공용 예산을 저장하고 실제 영수증과 모의계좌 링크를 보여줍니다. 기존 예산이 있으면 그 금액으로 진행합니다. |
| 튜토리얼 | 처음 한 번 “튜토리얼이 있습니다. 진행하실까요? 1 진행 / 2 건너뛰기”라고 묻습니다. 번호와 자연어로 진행하거나 건너뛸 수 있습니다. |
| 예제 과업 | 1 관심 분야의 시장 동향 조사·수집 / 2 유튜브 거래 기록으로 전략 분석 / 3 링크의 투자법으로 전략 분석 / 4 첫 모의 판단 또는 과거 시세 퀀트 실습 |
| 조사와 저장 | AI가 실제 원문을 읽고 MCP로 라이브러리·작성 양식·전략 노드 메타데이터를 조회합니다. 뉴스와 전략 분석은 출처와 함께 개인 라이브러리에 바로 저장하고 브리핑에 확인 링크를 제공합니다. 사용자가 조회만 요청하면 읽기만 합니다. |
| 이어서 하기 | 0 또는 ‘여기까지’로 멈추면 다음 대화에서도 중단 상태를 유지합니다. ‘튜토리얼 이어하기’라고 하면 완료한 항목의 링크와 남은 번호를 다시 볼 수 있습니다. |
| 실계좌 | 튜토리얼을 마칠 때 응답의 `liveConnection.offer`가 참이면 한 번 “1 지금 연결 / 2 나중에”를 안내합니다. 건너뛰거나 중단했다면 요청한 모의 과업을 이어갑니다. 지금을 고르거나 직접 요청하면 실전 계좌·자금 화면을 엽니다. 나중에는 `action: defer_connection`으로 저장하고 `links.paperResume`을 엽니다. 발급 중 돌아올 때도 같은 모의 결과를 열 수 있습니다. [계좌 연결과 잔고 확인](self-host.md#계좌-연결과-잔고-확인)에 따라 준비 상태와 조회 결과를 확인합니다. |

**3번 실습 예시**. [TradingView의 전략 문서](https://www.tradingview.com/pine-script-docs/concepts/strategies/)를 붙여 넣고 “체결·거래비용 가정을 요약해 내 자료에 저장해줘”라고 입력하세요. 원문에 공개일이 보이지 않으면 AI는 확인한 시각만 기록해 저장합니다. 원문을 열 수 없다면 다른 링크나 원문 일부를 보내거나 건너뛸 수 있습니다. 저장 링크를 열면 **투자 자료**에서 요약을 읽고 **출처·사용 시점**에서 원문과 수신 기록을 확인할 수 있습니다. 나중에 “튜토리얼 이어하기” 또는 자료 제목 검색으로 같은 결과를 다시 여세요.

MCP에서 공개일이 확인되지 않은 원문은 `publication.precision: "undated"`를 사용하며, `publishedAt`, `sourcePublishedValue`, `timezone`을 모두 `null`로 전송합니다. `retrievedAt`에는 원문을 실제 확인한 시각을 기록합니다. 앱에서 직접 저장할 때는 **공개 시점 기준 → 공개일 미확인**을 선택합니다.

1~3번의 저장 결과를 제공한 뒤 `viv_onboarding`에 `action: complete`, 과업 번호, 라이브러리 영수증의 `documentId`를 보냅니다. 사용자가 보기만 요청했으면 `readOnly: true`로 완료를 표시할 수 있습니다. 현재 확정 시세의 저장 판단을 실행한 4번은 `decisionId`를 보냅니다. 키 없이 완료한 기준 퀀트 백테스트는 `read_simulation_collection`에서 확인한 실험의 `simulationId`를 보내고, 응답의 저장 보고서 `openUrl`을 제공하세요. 진행·중단은 `resume`·`pause`로 기록합니다.

## 리서치 다시 열고 사용 기록 확인하기

1. **저장한 자료 찾기.** VIV가 연결된 AI에서 “내 투자 자료에서 ‘체결·거래비용’을 찾아 열어줘”라고 입력하고 반환된 링크를 엽니다. 앱의 **화면 찾기**(Ctrl/⌘+K)에 제목이나 발행자를 입력하고 **저장한 투자 자료**에서 버전을 고르세요. 더 많은 결과는 **투자 자료에서 결과 더 보기**로 이어집니다. 라이브러리에서 직접 찾을 때는 **자료 → 투자 자료 → 검색**을 열고, 이전 버전이 필요하면 **버전 → 모든 버전**을 선택하세요. 자료의 **출처·사용 시점**에서 원문과 해당 버전을 확인하세요. 문서의 특정 절을 저장할 때는 원문 주소에 `#` 앞까지 넣고 절 제목을 메모에 남기세요.
2. **읽기만 하려면 여기까지.** **저장됨** 상태의 자료는 JEV 키 없이 다시 읽을 수 있습니다. **공개일 미확인** 자료도 개인 참고용으로 읽을 수 있습니다. 나중에 공개 시점을 확인하면 **자료 작업 → 새 버전 작성**에서 그 시점을 기록한 뒤 판단 활용 절차를 진행하세요.
3. **판단 자료로 검토하려면 분류.** 공개 시점이 확인된 자료에서 **JEV에 보내 분류**를 누르면 자료 전체와 관련 승인 자료 최대 8개의 제목·요약·핵심 내용이 TypeSafe JEV에 전달됩니다. 사용량은 과금될 수 있습니다. 분류가 끝나면 **분류 상세**에서 결과와 응답에 기록된 사용량을 확인하세요. [TypeSafe 요금 안내](https://help.typesafe.ai/articles/5187202169-how-much-does-jev-cost)
4. **분류가 끊겼다면 상태부터 확인.** **분류 상태 확인**은 이미 보낸 요청의 결과만 조회합니다. 키가 필요하면 **JEV 키 설정 → 같은 자료로 돌아가기**, 402가 표시되면 **크레딧 확인 방법**을 이용하세요. **JEV에 다시 보내기**는 추가 사용량이 발생할 수 있는 새 요청입니다.
5. **승인과 실제 사용 확인.** 분류 결과와 출처를 확인한 다음 **검토·승인 → 검토 후 승인**에서 검토 사유를 남깁니다. **마인드에서 활용**에는 현재 정책에서 자료를 선택할 수 있는 마인드와 실제 전송 횟수가 따로 표시됩니다. 자료 버전을 고정하려면 **마인드에 연결**에서 대상을 고르고 정책 변경 미리보기를 확인한 뒤 **정책 초안 작성 → 검토·발행**으로 진행하세요. 자료를 구독 중인 마인드는 발행 후 고정한 버전을 사용합니다. 실제 사용은 **실제 전송**과 기록이 있을 때 표시되는 **전송한 결정 상세**에서 확인합니다. 전송 **0회**는 해당 버전이 전달된 기록이 없다는 뜻입니다.

**MCP에서 이어가기.** 제목으로 `read_market_knowledge`의 `search`를 사용하고, 결과의 각 `page.items[].openUrl`을 제공하세요. 정확한 `documentId`로 다시 조회하면 해당 버전의 `openUrl`, `classificationAttempt`, `entry.status`, `usage.eligibleMinds`, `usage.transmissionCount`를 확인할 수 있습니다. 조회에는 JEV 호출이 없습니다. 분류 응답이 끊기면 같은 ID로 조회하고, 사용자가 다시 보내기를 선택할 때 새 요청 키를 사용하세요. 이전 키로 재조회한 요청은 보관된 결과를 반환합니다.

실행용 프롬프트는 MCP의 `viv_start`와 `viv_onboarding` 응답에서 같은 내용을 제공합니다.
